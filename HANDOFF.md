# Qazir Travel: описание проекта для продолжения работы

Мини-апп для туристов из Казахстана, которые едут в Европу на 5-10 дней. Планировщик маршрута, бюджет, истории мест, тексты для Instagram Stories. Работает как сайт и как Telegram Mini App. Языки: казахский, русский, английский.

## Файлы

- `index.html` итоговый единый файл (1,7 МБ). Его выкладывают на хостинг или кладут в миниапп.
- `src/index.src.html` рабочий файл (340 КБ). Правки делать здесь.
- `src/thumbs.html` встроенные фото в WebP (1,4 МБ). Руками не править.
- `build.sh` склеивает рабочий файл и фото в `index.html`. После каждой правки запускать `./build.sh`.
- `tests/` проверки на Playwright (`npm i playwright`, затем `node tests/route_check.mjs` из папки проекта).
- `stories-kk.md` готовые тексты для сторис по 7 городам и 36 местам на казахском.

## Устройство `src/index.src.html`

1. Блок `<script id="qz-data">`: все данные в одном месте.
   - `FX` курсы, `BRAND` настройки сторис.
   - `TRAVEL` время и цена перегонов между городами (21 пара, ключ `"a|b"` симметричен).
   - `RETURN_FLIGHTS` как вернуться в Алматы или Астану.
   - `CITIES` одна структура на город: стикер, страна, история, факт, цены, магазины, точки с историями, рестораны.
   - `PHOTOS` путь и автор каждого фото. `PHRASES`, `CHECKS`.
2. Основной скрипт: словарь `T` на трёх языках, состояние `S`, маршрут, распределение дней, рендер, сторис, события.
3. Маркер `<!--THUMBS-->` в конце: здесь build подставляет фото.

## Ключевые решения

- **Маршрут.** `optimizeRoute` решает открытую задачу коммивояжёра с фиксированным стартом. До 10 городов точный перебор (Held-Karp), больше приближённый. При авто-финише учитывается время обратного вылета. Критерий только время, цена на выбор маршрута не влияет.
- **Дни.** `allocateDays`: каждому городу минимум 1 день, остаток по весу города.
- **Фото встроены в файл.** Причина: в телефонном просмотрщике сторонние сайты закрыты, а Wikimedia режет запросы и отдаёт по прямой ссылке только стандартные ширины 250, 330, 500, 960, 1280, 1920. При интернете обложки подменяются на 1280.
- **Сторис.** Основной способ: текст по абзацам, один абзац равен одной сторис, кнопка «Копировать». Картинка 1080x1920 без названия компании сверху и без фото лежит в свёрнутом блоке.
- **В английском режиме** произношение в разговорнике переводится в латиницу автоматически.

## Честность данных

- Цены среднего чека, цены перегонов, часы обратного вылета: оценки. В данных стоят пометки `confidence: "estimate"` и `verified: false`.
- Для цены перегона нижняя граница найдена в открытых источниках, верхняя граница оценка.
- `paris|venice` без цены: приложение пишет «цена не уточнена». Не подставлять придуманное.
- Перед запуском менеджер должен сверить цены, рейсы и часы работы по официальным сайтам.

## Следующие идеи по порядку

1. Подсказка по визе: консульство той страны, где больше всего ночей.
2. Предупреждения по датам: закрытые дни музеев, сезонные места, воскресенье в Вене.
3. Кнопка «Отправить план менеджеру» через Telegram.
4. Экран «Сегодня» с погодой.
5. Окупается ли проездной или городская карта.
6. Синхронизация плана через облако Telegram.
7. Данные в Google Sheets вместо правки файла.
8. Новые города: Прага, Будапешт, Барселона, Амстердам, Флоренция.

## Правила работы

- Не выдумывать цены, факты и рейсы. Нет данных значит пометить это.
- Любой текст на трёх языках. Не оставлять русских слов в английском интерфейсе.
- Только проверенные факты в историях мест, с источником.
- После правки: `./build.sh`, затем тесты из `tests/`, затем открыть на размере 390 px.
- Работать в `src/index.src.html`, не читать целиком `index.html` (там 1,4 МБ фото).
